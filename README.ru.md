# kairos

Калькулятор оставшегося времени жизни. Считает не «сколько лет осталось», а куда эти годы уже расписаны.

[English](README.md)

Греки различали два слова для времени: *chronos* — время как измеримое количество, *kairos* — время как качество и верный момент. Проект про перевод первого во второе.

## Проблематика

Такие калькуляторы обычно работают вычитанием: берут продолжительность жизни, отнимают сон, работу, дорогу, быт, остаток называют «настоящей жизнью». В этом методе два дефекта.

**Вычитание молча меняет единицы.** После вычитания сна остаток измеряется уже не в сутках. Любая следующая величина вида «часов в день», вычтенная из него, — бессмыслица. Расчёт, с которого начался проект, на этом шаге ошибся в 9.5 раза: получил 4 902 часа свободного времени там, где при тех же жёстких допущениях выходит 46 800.

**Вычитание выносит ценностное суждение под видом арифметики.** Оно утверждает, что работа, еда и дорога — не ваша жизнь. Ужин с близким человеком попадает в графу «еда, минус полтора часа». Это решение автора калькулятора, а не свойство мира.

Здесь всё накапливается в часах от единого горизонта и переводится в другие единицы только для показа. А каждая категория попадает в одну из трёх корзин, и распределяет их пользователь:

- **жизнь** — считаете прожитым;
- **плата** — цена существования;
- **утечка** — отдали бы обратно.

Один и тот же час у двух людей окажется в разных корзинах. Арифметика этого не решает.

## Модель смертности

Гомперц–Мейкем: `μ(x) = A + B·exp(C·x)`.

Параметры не подобраны на глаз: они генерируются скриптом [`tools/fit_mortality.py`](tools/fit_mortality.py) из таблиц дожития ВОЗ за 2021 год. На всех взрослых возрастах от 22 до 83 модель воспроизводит опубликованную ожидаемую продолжительность жизни с ошибкой не более **0.32 года**. Проверка живёт в тестах и сверяется с зафиксированной выгрузкой ВОЗ, а не с числами в комментарии.

Целевая функция — кривая `ex`, а не `mx`. Причина в весах: смертность в 20 лет на три порядка меньше, чем в 85, поэтому равномерная подгонка в логарифме коэффициентов даёт ошибку в 1–2 года по ожидаемой продолжительности — то есть ровно по той величине, которую читает человек.

Логистическое замедление смертности в глубокой старости пробовали и убрали: параметр неидентифицируем по сокращённым таблицам, закрывающимся на 85+, и оптимизатор уводил его к значениям порядка 1e-40.

**Период и когорта.** Таблицы ВОЗ замораживают сегодняшнюю смертность навсегда. За последние полвека возрастная смертность падала примерно на 1–2% в год. Поправка включается флагом и по умолчанию берёт осторожный 1%; для 22-летнего мужчины в России она сдвигает медианный возраст смерти с 70.6 на 76.0.

**Одного числа не существует.** Есть распределение, и оно широкое: между ранним и поздним исходом у того же человека 39 лет разницы. Калькулятор, который называет одну дату, врёт точностью, поэтому здесь везде показан диапазон.

## Рычаги

Величины, а не советы. Один час в день, удержанный до конца горизонта, стоит около двух с половиной лет — это единый обменный курс, и он выводится один раз.

Дальше сравниваются вещи с разной величиной: четырёхдневная неделя, работа из дома, отказ от пяти лет работы, лишние десять дней отпуска. Структурные решения почти всегда обходят ежедневную дисциплину, и список отсортирован по величине, а не по благородству.

Привычки в список попадают только из корзины «утечка». Ранняя версия подтягивала любую крупную категорию и предлагала срезать час сна тому, кто не переставил метку. Это переворачивает замысел: разметку делает пользователь, и арифметика не вправе её переигрывать.

## Данные

Ничего никуда не отправляется. Расчёт идёт в браузере, состояние лежит в адресной строке и в `localStorage`. Ссылка на расчёт — это и есть весь расчёт, и она читаемая: `age=22&sex=male&c=sleep-8-n_work-8-n_…`.

## Разработка

```bash
npm install
npm run dev
npm test
npm run build
```

Пересобрать константы смертности из API ВОЗ:

```bash
python tools/fit_mortality.py
```

Ядро в `src/core/` не знает про DOM и не импортирует ничего из `src/ui/`. Это не эстетика: тот же код будет считать данные трекера.

## Дальше

Вторая половина — не свой трекер активности. RescueTime, ActivityWatch, Rize, Timing уже существуют, и написать ещё один — потратить тысячи часов на воспроизведение готового.

Свободна ниша рядом. Все трекеры отвечают на вопрос «сколько сегодня». Ни один не отвечает на вопрос «сколько это стоило в масштабе жизни». Мост между дневной телеметрией и пожизненной бухгалтерией и есть содержание второй половины: события берутся из локального [ActivityWatch](https://activitywatch.net) по его REST API, раскладываются по тем же категориям и сравниваются с тем, что человек указал руками. Интересна разница между этими двумя числами.

Поэтому в [`src/core/taxonomy.ts`](src/core/taxonomy.ts) у категорий уже лежит поле `aw` с матчерами приложений и адресов, хотя калькулятор его не читает. Идентификаторы категорий — контракт между двумя половинами; переименование любого из них ломает совместимость.

Проект описания: [`docs/tracker.md`](docs/tracker.md).
